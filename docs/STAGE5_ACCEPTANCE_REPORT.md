# SuperCoder Stage 5 验收记录：重复资源识别

## 1. 结论

本阶段为 PRD 中唯一没有动工的"重复建设识别"建立了可计算的评测和一个离线检测器：先建数据集并冻结，再写检测器，阈值只在开发集上选择，测试集只打一次分。测试集 F1 为 **0.5385**，**未达到** PRD §7.4 的 0.82。标注由 AI 助手起草，与检测器出自同一个助手，**尚未经人工复核**，所有数字只对这份草稿数据成立。检测器尚未接入 API 与控制台。

| 范围 | 状态 | 说明 |
|---|---|---|
| 评测数据集 | **PASS** | 33 个变体、111 对；`build_duplicate_dataset.py --check` 通过；记录通过评测 Schema |
| 检测规则 | **PASS** | 每条规则有专门用例；6 处变异全部被测试检出 |
| 评测与基线复现 | **PASS** | 逐对复现归档基线；换 `PYTHONHASHSEED` 的子进程同样复现 |
| 测试集 F1 ≥ 0.82 | **FAIL** | 0.5385（精确率 0.700，召回率 0.438） |
| 标注人工复核 | **NOT RUN** | 全部为草稿；复核流程见第 3.4 节 |
| 接入 API 与控制台 | **NOT RUN** | 尚未开始；见第 8 节 |

## 2. 范围

### 2.1 本阶段包含

- **数据集**：一份手写、可审阅的规格（`evals/duplicates/stage5_spec.json`），由 `scripts/build_duplicate_dataset.py` 确定性地生成注册表扩展与配对、标注文件。
- **检测器**：`apps/api/search/duplicates.py`，确定性、不依赖模型与网络，每个判断附带证据。
- **评测**：`scripts/run_duplicate_eval.py`，包括只读开发集的调参、按切片统计、基线归档与复现检查。

### 2.2 本阶段不包含

- 接入登记预演和审核页，以及按调用者可见范围过滤候选。这需要修改冻结契约，按 `contract` 流程另行评审。
- 语义相似度。检索链路已有嵌入服务，但本阶段只做词法方法，以便评测可逐对复现。
- 输入输出接口的比较。语料中的接口字段是通用占位，没有区分力，检测器不读取它们。

## 3. 数据集

### 3.1 为什么另建

`evals/duplicates/pairs.jsonl` 只有 4 对，没有一对标为重复，F1 无从计算。重复资源也不能直接加进 `resources/`，那会改变 290 项检索语料和已归档的检索基线。所以变体放在独立的注册表扩展 `evals/duplicates/stage5_registry/` 中，布局与 `resources/` 相同，但不进入检索语料。语料一侧只读取 git 跟踪的资源，未跟踪的草稿不影响结果。

### 3.2 构成

每个变体模拟"另一个团队又登记了一遍"：

| 类别 | 数量 | 含义 | 例子 |
|---|---|---|---|
| 改写 | 10 | 用不同措辞重新登记同一能力 | `example-conventional-commit-writer` 对 `example-commit-message` |
| 原样复制 | 3 | 描述与正文不变，只改名称、slug 与团队 | `example-uuid-check` 对 `example-uuid-validator` |
| 换类型 | 3 | 同一能力登记成另一种资源 | 工具 `example-log-redactor` 被登记成 skill |
| 中文再登记 | 8 | 用中文重新登记同一能力 | `example-tijiao-xinxi` 对 `example-commit-message` |
| 用词相近但做另一件事 | 7 | 主题相同、职责不同 | 检查提交信息对生成提交信息 |
| 编排复用 | 2 | 工作流把原资源作为节点调用 | `example-release-readiness-gate` |

111 对中，正例 31 对（完全重复 3、近似重复 28），负例 78 对（相关 59、无关 19），不确定 2 对（计分时排除）。除变体外，还收入语料中天然存在的两对重复（`example-quality-report` 与 `example-data-quality-report`；`example-test-coverage-gap` 与 `example-coverage-gap-agent`）、Stage 0 的 4 对 demo 资源（沿用其草稿标注）和 10 对主题无关的基线负例。

中文再登记的 slug 不复用原 slug（例如 `example-tijiao-xinxi`），否则按字面比较的方法会从标识符直接拿到答案；`tests/test_duplicate_dataset.py` 检查这一点。

### 3.3 划分

资源按主题分成 24 个族，每个族整体归入开发集或测试集，同一资源不会同时出现在两个划分里。

| 划分 | 资源族 | 对数 | 正例 | 负例 | 不确定 |
|---|---|---|---|---|---|
| 开发集 | 12 | 54 | 15 | 37 | 2 |
| 测试集 | 12 | 57 | 16 | 41 | 0 |

两个划分的切片构成并不相同：测试集 16 个正例中有 7 个是跨语言，开发集 15 个中有 5 个。比较两个划分的数字时需要考虑这一点。

### 3.4 标注的来源与复核

标注由 AI 助手起草，与检测器出自同一个助手，没有人工复核。每条标注记录都写明了这一点：`x-label-author: ai-assistant`、`x-human-review-status: pending`、`adjudication_status: draft`。`assessor_type` 取 Schema 中唯一不表示人工或导入的取值 `deterministic-rule`，`provenance` 写清实际来源。

复核方式：在规格中修改 `label` 与 `rationale`，把复核过的 `pair_id` 列入 `reviewed_pairs`（生成的记录随之变为 `single-reviewed`），升级 `dataset_version`，重新生成，然后在开发集上重新选择常量并更新基线。

## 4. 检测器

### 4.1 三条规则

1. **复用不是重复。** 一方在 `dependencies` 中声明另一方，或工作流把另一方作为节点运行时，至多判为 `related`。
2. **完全重复。** 描述与入口正文（忽略标题行，规范化空白与大小写）相同，判为 `exact_duplicate`。
3. **加权相似度。** 用途文本（名称与描述）的 TF-IDF 余弦、正文的 TF-IDF 余弦、按 IDF 加权的标签重合度，三者加权。文本证据有下限：两路文本相似度都低于下限时不能判为重复，因此仅凭标签相同永远构不成重复。

每个判断附带三个分量得分、贡献最大的共同词和触发的规则，供审核者核对。

### 4.2 模板片段

示例语料反复出现同样的句子和代码行（例如"Report only what the input supports"、桩函数的文档字符串）。在注册表里至少 5 个资源中逐字出现的句子（散文）或行（代码）不携带"这个资源做什么"的信息，计算前剔除。阈值是对当前注册表的计数，不是手写清单。在 323 个资源上剔除了 65 个片段。

### 4.3 常量只在开发集上选择

`python scripts/run_duplicate_eval.py --tune` 遍历 1950 种组合（用途权重 0.3–0.7、标签权重 0–0.2、阈值 0.20–0.70、文本下限 0.20–0.40），只读开发集标签。选择规则依次为：开发集 F1 最高、精确率更高、标签权重更小、用途权重最接近 0.5，最后取剩余区间的中位。结果为用途 0.3、正文 0.5、标签 0.2，阈值 0.36，文本下限 0.30。

开发集上还比较过一处设计：IDF 去掉 +1 平滑。开发集 F1 从 0.6957 降到 0.6667，因此保留平滑。此后没有再改动设计。`tests/test_duplicate_detector.py` 检查模块常量等于调参结果，并检查把测试集标签全部翻转后调参结果不变。

## 5. 结果

### 5.1 总体指标

| 划分 | 精确率 | 召回率 | F1 | TP | FP | FN | TN |
|---|---|---|---|---|---|---|---|
| 开发集 | 1.000 | 0.533 | 0.6957 | 8 | 0 | 7 | 37 |
| **测试集** | **0.700** | **0.438** | **0.5385** | 7 | 3 | 9 | 38 |

测试集在常量确定后只打了一次分。

### 5.2 按切片（测试集）

| 切片 | 正例找到 | 负例误判 |
|---|---|---|
| 原样复制 | 1/1 | — |
| 语料中天然存在的重复 | 0/1 | — |
| 跨语言 | 3/7 | 0/2 |
| 换类型 | 1/2 | — |
| 改写 | 2/5 | — |
| 用词相近但做另一件事 | — | 1/10 |
| 同主题的相邻资源 | — | 2/19 |
| 编排复用 | — | 0/7 |
| 主题无关 | — | 0/5 |

找到的 3 个跨语言重复（`dp5-normalize-02`、`dp5-normalize-03`、`dp5-markdown-01`）都是与原资源共享同一份代码的工具；正文为中文散文的 4 个一个都没有找到。

### 5.3 错误分析

测试集 12 个错判分三类：

- **跨语言漏判 4 个**：`dp5-acceptance-01`、`dp5-flaky-01`、`dp5-sql-02`、`dp5-sql-03`。词法方法看不到中英文之间的对应。
- **改写与换类型漏判 5 个**：`dp5-sql-01`、`dp5-dependencies-01`、`dp5-incident-01`、`dp5-incident-03` 措辞几乎不重合；`dp5-coverage-01` 是语料中一个 skill 与一个 agent 实现了同一能力。
- **同主题但职责不同误判 3 个**：写验收标准与审查验收标准（`dp5-acceptance-02`）、改写 API 错误与改写堆栈信息（`dp5-api-errors-02`）、说明 SQL 结果与说明执行计划（`dp5-sql-04`）。

前两类需要语义信息，第三类需要理解"做什么"而不只是"关于什么"。这些都是词法方法的结构性局限，不是调参能解决的。

### 5.4 与丢失的 11-09 版本的关系

11-09 版本报告的测试集 F1 为 0.769，该版本的代码与数据没有保存下来。本阶段的数据集与检测器都是重建的，两个数字不可比，也没有为接近那个数字做任何调整。设计上借鉴了那一版的错误分析：文本证据下限从一开始就加入，没有像那一版那样在第一次测试集打分之后才补。

## 6. 复现命令

```bash

python scripts/run_duplicate_eval.py --by-slice        # 第 5.1、5.2 节的全部数字

python scripts/run_duplicate_eval.py --tune            # 第 4.3 节的常量选择（只读开发集）
python -m unittest tests.test_duplicate_dataset tests.test_duplicate_detector tests.test_duplicate_baseline
```

## 7. 已知限制

- **标注未经人工复核**，并且与检测器出自同一个助手：出题人和答题人相同，这会高估还是低估指标无法判断。
- **数据是合成的示例内容。** 变体由同一个助手按类别构造，真实团队的重复登记可能更杂乱。
- **只做逐对判断。** 产品中需要从全部可见资源里找候选；在约 300 个资源的规模上逐个比较可行，但没有评测"能否把原资源排进前几名"。
- **跨语言基本无能为力。** 正文为中文散文的再登记在两个划分中都没有被找到（开发集 0/5，测试集 0/4）。
- **未接入产品**，也就还没有可见范围约束：检测器本身不做授权判断，接入时候选只能来自调用者可见的资源。
