# 检索分数分离分析

> 目的：决定"能力发现 Agent"的**无证据拒答**该靠什么实现。
> 数据：`evals/retrieval/stage2_queries.jsonl` / `stage2_qrels.jsonl`，混合检索，top-10。
> 产物：`evals/results/score-separation-analysis.json`、`rerank-effect-analysis.json`

---

## 1. 结论先行

**不能用分数阈值决定拒答。**

相关与否的分数在查询之间**不可比**：

- 有相关结果的查询，最低 top-1 分数是 **0.0007**
- 没有相关结果的查询，最高 top-1 分数是 **0.9582**

两者完全交叠。任何阈值要么大量误拒可回答的查询，要么放行不可回答的查询。

**拒答必须靠"显式判断 + 可核查证据"，不能靠一个数字。**

---

## 2. 三个分开的问题

### Q1. 在一个"有答案"的查询内部，相关结果是否排得靠前？

**是。**

56 条有相关结果的查询中，50 条（**89.3%**）的相关结果分数高于所有不相关结果。

分数分布（n=60）：

| | min | p25 | median | p75 | max |
|---|---|---|---|---|---|
| 最佳相关结果 | 0.0007 | 0.0412 | 0.1451 | 0.6911 | 0.9847 |
| 最佳不相关结果 | 0.0001 | 0.0025 | 0.0152 | 0.0596 | 0.9582 |

**含义**：查询内部排序是有效的，排序指标（Hit@5 / MRR / NDCG）可信。

### Q2. 跨查询能否用单一阈值判断"有没有证据"？

**不能。**

| | 值 |
|---|---|
| 无相关结果的查询，最高 top-1 | 0.9582 |
| 有结果的查询，最低 top-1 | 0.0007 |

如果把阈值设在 0.9582 以上，会误拒 **53/56（94.6%）** 本可回答的查询。
如果设在 0.9582 以下，那条无答案查询就会被当成有答案。

之前算出的"最佳阈值 0.0394，池准确率 72.4%"是**用样本事后优化出来的上界**，不是可用的工作点。

**根因**：分数反映的是"这条查询在当前语料下的匹配强度"，而查询本身难易不同。一个宽泛查询对所有文档都给低分，一个精确查询对所有文档都给高分。

### Q3. 精排是帮忙还是拖后腿？

**整体是帮忙的。**

同一批 80 条查询，只切换精排开关：

| 配置 | Hit@5 | MRR | NDCG |
|---|---|---|---|
| 开精排 | **0.950** | **0.874** | **0.719** |
| 关精排 | 0.900 | 0.787 | 0.671 |
| 差值 | **+0.050** | **+0.088** | **+0.049** |

**保持精排开启。**

## 3. 发现的一个真实检索缺陷

排查过程中发现 `s2q15`（查询 `workflow approval human`）完全失败：

| 阶段 | 目标 `workflow/demo-review-flow` 的位置 |
|---|---|
| BM25 | **第 1 名**（分数 73.87） |
| 混合检索 + 精排 | **第 14 名** |
| 混合检索 无精排 | **第 1 名** |

精排把正确答案从第 1 挤到第 14。

**但这不是 bug，是精排的取舍。** 上面 Q3 证明精排整体 +0.05 Hit@5。单点失败被整体收益覆盖。

**如实记录**：这类失败存在，约占 5%（80 条样本中 4 条完全失败）。

## 4. 对发现通道的设计约束

### 拒答怎么做

不能是：

```python
if top_score < 0.3:
    return "没有找到相关能力"
```

必须是：

1. **由 LLM 显式判断**：给模型候选列表（含名称、描述、匹配字段），让它判断"这些候选能否回答用户问题"
2. **判断必须点名证据**：拒答时要说清"我看了哪几个候选，为什么都不够"
3. **可核查**：拒答理由里引用的资源必须真实存在于候选列表中
4. **不越权**：LLM 只判断"相关性"，不判断"能不能用"——后者是权限与生命周期的事，由服务端决定

### 阈值还能用在哪儿

可以用作**候选裁剪的下限**（低于某分数不进候选列表），但不能用作**拒答决策**。

两者区别：
- 裁剪错了 → 少给几个候选，LLM 还能从剩下的判断
- 拒答错了 → 用户直接被告知"没有"，无从纠正

## 5. 复现方式

```bash
# 1. 分数分离分析（需要 embedding/rerank，不需要 LLM）
python <分析脚本> 60

# 2. 精排效果对比
python <分析脚本> 80
```

原始数据见 `evals/results/score-separation-analysis.json`（含每条查询的 top-1 分数与最佳相关/不相关分数）。

---

## 6. 限制

1. 样本为**前 60 / 80 条查询**，不是随机抽样；顺序不影响结论但会影响精确数值
2. 4 条"无相关结果"的查询在样本中占比很小（60 条里 4 条），Q2 的结论基于这 4 条
3. 分析用的语料是**构造的示例数据集**，真实企业环境下分数分布可能不同
4. **单标注者**——"相关"由一人判定，若标注有误，结论会被同步影响
