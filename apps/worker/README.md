# Worker 应用包边界

`apps/worker` 是 SuperCoder 异步任务执行面的预留应用包。本文冻结阶段 0 的执行边界；本目录当前**不包含、也不声称包含可运行的 Worker、队列消费者或调度服务**。

## 阶段 0 契约

Worker 通过持久化 Job/Job Event 契约承接耗时、可重试或有副作用的工作：

- 输入必须引用已持久化的任务、调用者、资源版本、权限快照和可审计配置，不接受来源不明的任意指令。
- 输出必须包含结构化状态、事件、产物引用、错误分类、重试信息和 Trace 关联标识。
- Redis 可用于队列、锁、进度和短期上下文，但 Job、关键事件与审计事实必须落入 MySQL。
- 资源正文和脚本来自受版本约束的 Git 内容；向量索引属于可从 Git 与 MySQL 重建的派生数据。
- 外部 LLM 默认禁用；Secret 只能由受控配置注入，不得来自资源正文、任务参数、日志或模型输出。
- 资源正文、Prompt、MCP 返回内容和外部模型响应均是不可信数据，不能修改 Worker 的系统策略、权限或审批规则。

## 职责

阶段 1 及后续实现后，本包负责：

1. 领取、续租、执行、取消和恢复持久化 Job，并保证并发安全和可观察性。
2. 执行资源校验、敏感信息扫描、重复检测、索引构建、评测和批量导入等后台任务。
3. 按正式 Workflow 定义执行节点、条件、重试和检查点，在关键动作前等待人工审批。
4. 通过受控适配器调用 Embedding、Rerank、LLM、MCP 和确定性 Tool，执行前校验权限及运行环境兼容性。
5. 对代码或命令执行应用最小权限、超时、资源限制、沙盒和输出大小限制。
6. 持久化状态转换、Job Event、Trace、产物引用、失败原因和审计记录，支持幂等重试与中断恢复。
7. 将终态和进度回写到 API 可查询的数据边界，不依赖进程内状态作为唯一记录。

## 明确不负责

- 不提供面向浏览器的业务 REST API，也不渲染 Web 页面。
- 不接受 Web 绕过 API 直接创建或操纵任务。
- 不自行批准资源、提升权限、跳过人工审批或把模型声明视为任务完成证据。
- 不把 Redis 队列、内存状态、Qdrant 索引或日志文件当作不可替代的事实源。
- 不执行未登记入口、未解析依赖、未校验权限或未进入受控沙盒的任意代码。
- 不在日志、事件、Trace 或产物中泄露 Secret。

## 与其他应用包的关系

- `apps/api` 创建和控制 Job，并从持久化状态提供查询、取消和 SSE；Worker 不与 API 共享进程内对象。
- `apps/web` 不直接访问 Worker；所有可见进度和结果均经 API 暴露。
- `resources` 与 `schemas` 提供资源和入口契约；Worker 只执行通过 Schema、生命周期、权限、依赖和运行环境检查的明确版本。

## 阶段 1 实现入口

阶段 1 将在本目录建立 Python Worker 入口，约定入口模块为 `apps.worker.main:main`，并划分 `jobs`、`executors`、`adapters`、`sandbox`、`persistence` 和 `telemetry`。初始实现必须先支持安全领取、租约、心跳、幂等、取消、重试、终态持久化和故障恢复，再接入具体任务处理器；只有队列、数据库、取消、重试和恢复测试通过后，才可宣称 Worker 可运行。

## 当前完成声明

本 README 仅证明 Worker 的任务协议、信任边界和未来入口已冻结。它不证明队列已部署、消费者已启动、任务可执行、沙盒已生效、外部服务已接入或 Workflow 已完成端到端运行。
